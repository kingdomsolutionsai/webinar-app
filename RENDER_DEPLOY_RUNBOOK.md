# Webinar App → Render: Deploy Runbook

Everything in this repo is already converted off Manus. Tonight's code work is done and the
database layer is verified. Tomorrow is the account/click work below, in order. Budget ~60–90 min.

**What changed from the Manus version (so nothing surprises you):**
- Database: **MySQL → Postgres** (Render's native DB). Schema, dashboard, and all features unchanged.
- Login: **Manus OAuth → a single-admin email + password** login page at `/login`. Just you.
- Scheduler: **Manus cron → a Render Cron Job** that calls `/api/scheduled/sequence` hourly with a shared secret.
- Assets: **Manus storage → served locally** from `public/downloads/` (chapter, checklist, logo, cover are all included in this repo).
- No registrant data to migrate — there were zero signups, so we start with empty tables.

---

## Step 1 — Push this repo to GitHub

1. Create a new repo, e.g. `kingdomsolutionsai/webinar-app` (private is fine).
2. Push these files to it. (If you'd rather, I can give you the exact git commands.)
   - Note: `public/downloads/` contains the real PDFs/images (~11 MB) — that's intended; they must ship with the app.

## Step 2 — Generate your admin password hash

Your password is never stored in plaintext. On any machine with Node, run:

```
node -e "console.log(require('bcryptjs').hashSync('YOUR_PASSWORD_HERE', 10))"
```

Copy the output (starts with `$2a$10$…`). That's your `ADMIN_PASSWORD_HASH` for Step 4.
(If you don't have Node handy, tell me and I'll generate it for you tomorrow.)

## Step 3 — Create everything from the Blueprint

1. In Render: **New → Blueprint**, connect the GitHub repo from Step 1.
2. Render reads `render.yaml` and proposes: a **Postgres database**, a **web service**, and a **cron job**.
3. Approve it. `DATABASE_URL`, `JWT_SECRET`, and `CRON_SECRET` are wired/generated automatically.

## Step 4 — Set the four secret values

On the **web service → Environment**, fill the four values marked "sync:false":

| Key | Value |
|---|---|
| `BREVO_API_KEY` | your Brevo API key |
| `ADMIN_EMAIL` | the email you'll log in with |
| `ADMIN_PASSWORD_HASH` | the hash from Step 2 |
| `PUBLIC_URL` | for now, the Render URL (e.g. `https://webinar-app.onrender.com`); switch to the real domain in Step 7 |

On the **cron job → Environment**, set `PUBLIC_URL` to the same value.

## Step 5 — First deploy + create the tables

- The build runs automatically: `npm install && npm run build && npx drizzle-kit migrate`.
- `drizzle-kit migrate` creates the 5 tables in Postgres from the verified migration in `drizzle/`.
- **If the build fails**, it's most likely one of two known follow-ups (send me the log and I'll fix fast):
  1. A leftover Manus `_core` utility (llm/map/dataApi) that needs pruning.
  2. The client static-path resolution (`vite.ts`) may need a one-line tweak for Render's layout.
- These are expected first-build items — quick to resolve once we see the actual error.

## Step 6 — Test on the Render URL (before touching DNS)

1. Visit `https://<your-render-url>/` → registration page loads.
2. Submit a **real** test registration → check that **both** emails arrive and the sample chapter / checklist links download.
3. Go to `https://<your-render-url>/login` → sign in with your admin email + password → the dashboard loads and shows your test entry.
4. Manually fire the sequence once to confirm the cron path works:
   ```
   curl -X POST -H "x-cron-secret: <CRON_SECRET from Render>" https://<your-render-url>/api/scheduled/sequence
   ```
   Expect `{ "ok": true, ... }`.
5. Click an unsubscribe link from a test email → confirm it validates.

## Step 7 — DNS cutover (only after Step 6 passes)

1. In Render (web service → Settings → Custom Domains), add `whatentrepreneursneedtoknow.com`.
2. In **GoDaddy**, point the domain to Render per the DNS records Render shows you (replaces the Manus/AWS records).
3. Update `PUBLIC_URL` (web service **and** cron) to `https://whatentrepreneursneedtoknow.com`.
4. Wait for DNS to propagate, then re-run the Step 6 tests against the real domain.

## Step 8 — You're off Manus

Once the real domain serves from Render and tests pass, Manus can delete (Aug 23–25) with nothing lost.
